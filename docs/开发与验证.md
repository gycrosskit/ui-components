# 开发与验证

## 日常构建入口

日常编译由项目维护命令，CI 只调用 `bash scripts/build.sh compile --platform android|ios|harmony`，不串联 MR、测试或独立消费者。平台参数每次选择一个；这里只编译生产模块，iOS/ArkTS 原生消费与设备验收分别记录。

Maven 打包沿用项目脚本，通过 `VERSION=<不可变版本> bash scripts/build.sh package --platform maven` 调用，不上传、不创建 Tag；本库没有独立 HAR 打包渠道。发布任务复用既有 publisher、版本保护与 journal，未做消费时明确记录未消费，不把打包成功视为宿主验收。下文测试及消费命令按需要单独执行，不进入日常构建。


SDK 重任务必须通过 GY CrossKit 统一 `ci.py component-run` 的受控 Mac 入口，不直接在候选仓库绕过容量准入。
正式版本 `1.0.0` 已发布。以下为该入口调用的任务合同；当前已通过的公开消费范围见文末，不据任务声明推定其他检查通过。

- 源码回归：`:ui-components:testDebugUnitTest`，从本轮 XML 确认实际运行 common 与 Android 测试。
- 编译：Android debug/release、iOS arm64/x64/Simulator arm64、OHOS arm64，均保留宿主工具链版本。
- 归档：`VERSION=1.0.0 bash scripts/archive-prebuilt.sh`，产生 `build/prebuilt/ui-components-maven.tar.gz`。
- 预构建归档采用 metadata/check-maven 模板，含精确六项 publication。Jenkins 随 Maven Release 提供来源回执和摘要，JitPack 校验后安装同一制品。

`verification-consumer` 是独立构建，默认只从 JitPack 解析精确 `uiComponentsVersion`；候选检查使用 `-PuiComponentsMavenRepo=<staging URL>`。
`-PremoteOnly` 强制 JitPack，不使用 MavenLocal、源码替换或候选仓库。

受控任务运行 `assembleDebug minifyReleaseWithR8 verifyNoCmpUi`，覆盖真实 AAR 编译/D8、R8 和无第二套 UI 的完整依赖图；另运行 `compileKotlinOhosArm64` 与 iOS 编译/链接。
iOS consumer 链接通过 `-PkuiklyRenderFrameworkDir=<真实 2.30.0 Renderer 目录>` 提供匹配的 framework，不以占位符号代替。

源码迁移基线为宿主 SHA `c768cb12c86e59b60fbc69149013850edce509b0`；生产 Kotlin 与回归源码按字节保留。
`1.0.0` 已完成[正式发布](https://github.com/gycrosskit/ui-components/releases/tag/1.0.0)、公开产物核验与独立消费者编译；结果绑定对应源码/CI SHA 和执行收据。宿主主题、输入/窗口接线及设备表现仍须单独验收，组件公开消费不替代宿主验收。

依赖缓存沿用调用方提供的 `GRADLE_USER_HOME`、`KONAN_DATA_DIR`、`CP_CACHE_DIR`、`GRADLE_RO_DEP_CACHE`，编译与打包使用同一组目录。项目入口不清理这些缓存，也不强制刷新依赖；Maven、Google 与插件仓库镜像由本项目 `settings.gradle.kts` 和已有 `scripts/ci-repositories.gradle`（如存在）维护。CI 仅统一 GitHub 出站代理。
